# КВОРДЛИ

Отдельная русскоязычная Mini App для четырёх слов. Кнопка в тестовом
`@tg_template_test_bot`: **«Игры 🕹» → «КВОРДЛИ»**. Команда `/quordle`
сразу открывает приглашение. На полном тестовом Copilot в этом меню две
игры. Рабочие службы не запускаются этим стендом.

## Правила

- У четырёх полей 9 общих ходов. Одно принятое слово проверяется отдельно
  на каждом открытом поле. Клетки активной строки крупнее остальных.
- Жёлтый — точная позиция, белый — другая позиция, серый — буквы нет
  или её повтор лишний. Сначала учитываются совпадения на точных позициях.
  Четыре сектора клавиши относятся к четырём полям и окрашиваются только
  после проверки слова. Решённое поле не принимает новые ходы:
  его сектора сохраняют прежние подсказки без дополнительной заливки.
- Касание ячейки на любом открытом поле перемещает общий курсор и позволяет
  исправить букву. Подсказки верных позиций видны только на своём поле и
  не заполняют общий черновик. `Ё` равна `Е`. Ошибка словаря хода не тратит;
  повтор допустимого слова тратит ход.
- Для победы требуются все четыре слова. В результате показываются четыре
  карточки без цепочки: решённое слово выделено жёлтым и отмечено галочкой,
  неотгаданное — серым. Определения доступны у всех показанных ответов
  текущей партии по наведению или касанию. Нераскрытые ответы и архив
  прошлых партий недоступны.
- Слова берутся из локального словаря «5БУКВ» без изменений: 2 083 слова
  можно вводить, 1 758 — выдавать. У каждого игрока своё перемешивание.
  Когда остаётся меньше четырёх слов, берётся новый цикл из полного набора.
  Пройденные партии и рейтинг не обнуляются.
- Сутки сменяются в 00:00 UTC. Просрочка не поражение и не попадает в
  рейтинг. Если есть угаданные слова, доступен последний просроченный
  результат: определения раскрытых слов доступны, оставшиеся ответы скрыты.

В интерфейсе раздел «Правила» начинается с общего блока «5БУКВ». Ниже
описаны четыре поля, девять общих попыток и подсветка клавиатуры КВОРДЛИ.

## Баллы и рейтинг

**Партия** — одна четвёрка слов. **Победа** — только 4/4. **Угаданные слова**
учитываются отдельно: например, 3/4 — одна завершённая партия, ни одной
победы и три угаданных слова. Победы распределяются по ходам 4–9.

| Исход | Балл партии |
|---|---:|
| Поражение, 0–3 угаданных слова | 10 × число угаданных слов |
| Победа за `h` ходов | 60 + 8 × (9 − `h`) |
| Активная или просроченная партия | Не участвует в расчёте |

Пример: 3/4 — 30, победа за девять ходов — 60, за семь — 76, за четыре — 100.
После пяти завершённых партий берём среднее всех их баллов, умножаем на 100
и округляем до целого. Например, баллы 30, 60, 76, 100, 0 дают рейтинг
**5 320**. Это среднее, а не сумма: новый результат ниже предыдущего
среднего может снизить рейтинг даже при победе. Экран результата показывает
число попыток, но не балл отдельной партии.

## Тестовый стенд

Стенд не использует корневой `.env` и не меняет данные «5БУКВ». Запуск
обоих Telegram-сервисов проверяет настоящий username `@tg_template_test_bot`
и ID из `local_testing/.env.test.local`. Доступ к игре имеют только
настроенные `OWNER` / `ADMIN_LIST`. Реквизиты не выводятся и не коммитятся.

1. Выделенный контейнер `copilot-quordle-postgres`: PostgreSQL 15, порт
   `127.0.0.1:55492`, база `copilot_quordle_test`, пользователь
   `quordle_test`, отдельный том `copilot_quordle_test_data`. Его
   `--env-file` — `local_testing/data/quordle-runtime/postgres.env` с именами
   `POSTGRES_DB`, `POSTGRES_USER` и `POSTGRES_PASSWORD` (случайные 64
   шестнадцатеричных символа). Не менять этот пароль в файле независимо от
   уже инициализированного тома. Не использовать рабочий PostgreSQL.
2. Локальный `cloudflared.exe` запускается под Windows с
   `tunnel --no-autoupdate --protocol http2 --url http://127.0.0.1:8792`.
   Из его лога берётся свежий HTTPS-адрес Quick Tunnel. После перезапуска
   туннеля этот адрес меняется.
3. Для «5БУКВ» используется её штатный тестовый API
   `prototypes.wordli.telegram_server` на отдельном порту и с отдельным
   Quick Tunnel. Его HTTPS-адрес указывается как `WORDLI_WEBAPP_URL`
   в локальном `.env.test.local`. Игровые исходники менять не нужно.
4. Из корня репозитория в двух терминалах (с одинаковым `$origin`):

   ```powershell
   .\local_testing\venv\Scripts\python.exe -B -m prototypes.quordle.server --origin $origin
   .\local_testing\venv\Scripts\python.exe -B -m prototypes.quordle.full_test_bot --url $origin
   ```

5. Открыть чат тестового бота, `/start` → «Игры 🕹», затем кнопку. Проверка API:
   `/health` отвечает без авторизации, запросы партии требуют подписанное
   Telegram `initData`. Напоминания выключены по умолчанию; при включении
   отправляются в 05:50–06:10 по указанному часовому поясу, только если
   первая партия дня ещё не завершена.

Полный тестовый бот использует штатные обработчики Copilot и локальные
фотофикстуры. Адаптер только добавляет «КВОРДЛИ» рядом с «5БУКВ» внутри
штатного раздела «Игры» для тестеров. Погода и валюта требуют отдельных
тестовых ключей провайдеров; ключи из рабочей среды не подставляются.
Не запускать `demo_bot`, `run_test_bot` или другой polling параллельно
с `full_test_bot` на том же токене.

Для браузерного теста без Telegram:

```powershell
.\local_testing\venv\Scripts\python.exe -B -m prototypes.quordle.server --preview --port 8793
```

Этот процесс доступен только на loopback и использует искусственного игрока.
Не подключать к нему публичный туннель. Для остановки завершить только
процессы КВОРДЛИ и выполнить `docker stop copilot-quordle-postgres`. Том
с тестовыми партиями не удалять.

## Проверки

```powershell
$env:QUORDLE_RUN_DB_TESTS = '1' # включить только при поднятом отдельном Docker PostgreSQL
.\local_testing\venv\Scripts\python.exe -B -m unittest -v prototypes.quordle.test_engine prototypes.quordle.test_integration prototypes.quordle.test_full_bot
node --check prototypes/quordle/quordle.js
```

Без `QUORDLE_RUN_DB_TESTS` проверка с PostgreSQL пропускается. У неё
отдельный временный профиль; тестовые игроки Telegram не меняются.
