# «5БУКВ»: локальная игра и тестовая Telegram Mini App

Есть два независимых запуска: локальный просмотр с сохранением браузера
и тестовая Mini App с подтверждением Telegram и серверной тестовой БД.
Настройки и ограничения первого режима ниже относятся к `local_server`.

Правила и статистику проверяет Python. Браузер отвечает за согласованный
интерфейс и собственное локальное сохранение. Telegram, файлы настроек бота,
PostgreSQL, Redis и рабочие данные не используются.

## Запуск

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe -B -m prototypes.wordli.local_server --port 8765
```

Адрес: <http://127.0.0.1:8765/>. Для запуска игры нужна только стандартная
библиотека Python, установка новых пакетов не требуется.

Старый `python -m http.server` и прямое открытие `index.html` больше не подходят:
они не умеют проверять ходы. Если порт занят, остановите только собственный
прежний просмотр либо выберите `--port 8766`. Не останавливайте неизвестные
процессы ради освобождения порта.

## Правила

- Пять букв, шесть допустимых попыток, персональное первое слово на игровой день.
- Смена суток — **00:00 UTC**, дату определяет локальный Python-сервер.
- «Ё» равна «Е», регистр не важен; похожая латиница не подменяется русскими буквами.
- Жёлтая клетка — точная позиция, белая — буква в другом месте,
  серая — отсутствующая или лишняя повторная буква.
- Сначала учитываются точные совпадения, затем оставшиеся буквы ответа.
- Неизвестное слово и неверный формат не расходуют ход.
- Намеренный повтор допустимого слова расходует обычную попытку.
- После победы или шестой ошибки партия завершена. Через 3,5 секунды
  открывается результат с количеством попыток и кнопкой «Играть ещё раз».
- Дополнительные слова доступны после любого завершения и входят в общую
  статистику; отдельного режима безлимита нет.
- Каждая новая победа запускает конфетти, без повтора при перезагрузке.
  Буквы раскрываются по очереди, клавиатура — сразу.
- Неизвестное слово подсвечивается красным и слегка встряхивается;
  белая подсказка остаётся до следующего касания или действия игрока.
- В завершённой партии показывается ответ; защищённый Telegram API не выдаёт
  ответ активной партии. Локальный отладочный режим хранит закреплённый ответ
  в браузерной истории и не предназначен для защищённого рейтинга.
- Незаконченный истёкший день не считается поражением.

Выданный ответ и его версия словаря закрепляются в истории. Все ранее
выданные ответы исключаются из следующих партий этого игрока, включая
поражения и незавершённые просроченные партии. Смена дня не записывает
поражение. Разные игроки могут получить разные слова; совпадение слов
между разными игроками допустимо. После исчерпания набора повторов нет:
показывается «Все слова сыграны», статистика остаётся доступной.

Исходный словарь сохранён в `data/archive`. Старые записи восстанавливаются
по прежним правилам и получают закреплённый ответ; расширение словаря
не переигрывает прошлые партии. Неизвестная версия отклоняется без сброса.

## Словарь

`data/ru5.json` содержит **2083 допустимых слова**, из них **1758** входят
в более частотный набор ежедневных ответов. Набор подготовлен с морфологическим
и частотным отбором, исключением имён/брендов/сокращений и проверкой кандидатов.

Полная экспертная вычитка всех слов не заявляется: пограничные случаи можно
уточнять после ручных игр. Происхождение, версии, контрольные суммы, правила
отбора и лицензии находятся рядом с данными. Инструменты подготовки не нужны
для запуска и не устанавливаются в окружение бота.

## Сохранение и статистика

История и текущая строка сохраняются только в `localStorage` этого браузера,
ключ `wordli.local.v01`, формат версии 3 с закреплённым ответом и словарём.
Прежние форматы версий 1 и 2 читаются
без сброса: записи без `index` становятся первыми ежедневными партиями
с индексом 0, дополнительные имеют индексы 1 и далее.
Используйте тот же адрес и порт: `localhost`,
`127.0.0.1` и другой порт являются разными адресами сохранения.

Python пересчитывает исходы по словам, а не доверяет сохранённым значениям
победы, раскраски или процента. Новая история начинается с пустого поля
и нулевой статистики: демонстрационных 39 партий больше нет.

- Сыграно: победы + поражения, без просрочек и незавершённых партий.
- Процент: победы / сыграно × 100.
- Среднее: попытки только в победных партиях / количество побед.
- Текущая серия: последовательные завершённые победные партии,
  пропуски дней и просрочки игнорируются; поражение обнуляет серию.
- Максимальная серия: наибольшая обычная серия побед.
- Гистограмма 1–6 учитывает только победы.

Карточки: «Всего сыграно», «Доля побед», «Попыток на победу» /
«Максимальная серия», «Текущая серия», «Очков». Прежний внутренний показатель
календарной непрерывности сохранён для совместимости, но не отображается
и на очки не влияет.

### Очки v2

До 5 завершённых игр отображается `—`. Затем используются целые очки
от 0 до 10000, без очков за просрочки и незаконченные партии:

```text
N = число завершённых игр
W = число побед
A = среднее число попыток в победах
M = максимальная серия побед без поражений
K = количество ответов в текущем словаре (1758)
Q = (7 - A) / 6
Очки = floor(10000 × sqrt(min(N, K) / K) × (W / N)
             × (0.4 + 0.4 × Q + 0.2 × sqrt(min(M, K) / K)))
```

Если побед нет, очки равны 0, среднее не вычисляется. Результат ограничен
диапазоном 0–10000. Поражение может уменьшить очки. Идеальное прохождение
всего набора с первой попытки даёт 10000. Версия формулы:
`progress-quality-v2`. Это собственная шкала, не Elo. При будущей смене
размера словаря оценки пересчитываются
относительно нового K; изменение требует отдельного согласованного обновления.

Рядом с очками мелким серым текстом показывается разница за последнюю
завершённую партию: текущие целые очки минус оценка до этой партии.
Нулевая разница и первое начисление скрыты. Незавершённые и просроченные
партии не заменяют последнюю дельту; повторное открытие статистики её не
сбрасывает. Расчёт одинаков на устройствах и не требует новой таблицы БД.

### Редактирование строки

В активной строке можно выбрать любую ячейку мышью или касанием и заменить
букву, не удаляя остальное слово. Пустые позиции сохраняются пробелами;
ведущие и внутренние пробелы не сдвигают буквы при восстановлении.
Подсказки верных позиций берутся только из уже проверенных ходов.
Они не блокируют редактирование и сами не заполняют пустые ячейки:
для отправки нужны пять явно введённых букв.

### Настройки, формула и рейтинг

В настройках находятся «Правила», «Формула / расчета очков» и
«Рейтинг / топ участников». Формула показана одним серым блоком;
само выражение выделено более светлой скруглённой подложкой.
K соответствует набору загадываемых ответов, а не расширенному списку
слов, разрешённых для ввода.

Защищённая Telegram-игра показывает общий рейтинг после пяти завершённых
партий. Публичное имя берётся только из подписанных Telegram-данных.
У прежних профилей имя появится при следующем открытии игры; до этого
используется нейтральное «Игрок». Имена для рейтинга не читаются из таблицы пользователей.
Порядок: очки по убыванию, затем число завершённых игр по убыванию.
Равенство обоих показателей даёт одинаковое место: 1, 2, 2, 3.
Отсечка топ-10 означает десять участников, а не десять различных мест.
Ниже десятки видны первые пять участников, небольшой отступ и окно из пяти
участников вокруг игрока. Если двух строк после него не хватает,
показываются четыре участника выше и сам игрок последней строкой.
Перед первым участником и в разрыве таблицы линий нет; пустой отступ сохранён.
Имя показывается одной строкой: максимум 14 видимых символов и две точки `..`
сверх этого предела при сокращении. На узком экране имя дополнительно подгоняется
по доступной ширине; полное значение в API и БД остаётся неизменным.

### Напоминания

Переключатель по умолчанию выключен. Часовой пояс IANA определяется
браузером при открытии приложения и сохраняется на сервере; резервный
пояс — UTC+4. Для каждого местного дня случайно выбирается время между
05:50 и 06:10. Завершённое первое ежедневное слово (победа или поражение)
отменяет напоминание. Смена игрового слова по-прежнему происходит в 00:00 UTC.

Под текстом напоминания находятся две inline-кнопки одна над другой:
«5БУКВ» открывает игру по настроенному адресу этого сервера, а
«Назад на главную ↩️» удаляет именно напоминание и возвращает главное меню.
Устаревшая ссылка на другое сообщение в состоянии диалога не используется.
Текст и кнопка возврата используют выбранный в боте язык из `users.locale`.
Для нерусских локалей приглашение и напоминание дополняются предупреждением
о русском языке игры через одну пустую строку. Для русской локали пометки нет.
Для будущей production-выкладки нужен отдельно проверенный доступ игрового
процесса только к `users.user_id` и `users.locale`; см. `PRODUCTION.md`.

Настоящую отправку отдельно включает `WORDLI_REMINDERS_ENABLED=true` на
игровом сервере. Без этого переключатель сохраняет предпочтение, но сервер
не отправляет сообщения. Локальный просмотр без Telegram ничего не рассылает.
Неопределённый результат сетевой отправки не повторяется автоматически:
в редкой ситуации сбоя напоминание может быть пропущено, но не продублировано.

Цепочка на результате показывает победы за всё время блоками 1–5, 6–10
и далее. Пять завершённых точек остаются видимыми до шестой победы.
Поражения не продвигают цепочку. Под будущими точками находятся пять маленьких
серых кружков вместо букв; ответ не раскрывается.

Перезагрузка восстанавливает поле и черновик. Повторный Enter во время запроса
блокируется; вкладки синхронизируют сохранение. При повреждении или
недоступности хранилища приложение предупреждает, а не выдаёт сохранение
за успешное. Ошибки сети не списывают ход. Новый день обновляет поле без
поражения за просрочку.

Физический ввод во время запроса ставится в очередь, а набор следующей
строки не блокируется анимацией предыдущей. Enter во время раскрытия
выполняется после него. Фокус поля сохраняется при обновлении экранных
кнопок, в том числе на шестой попытке.

## Ограничения локального этапа

- Нет Telegram-авторизации и синхронизации между устройствами.
- Историю можно изменить средствами браузера: это не защищённое серверное
  хранилище и не основа для рейтингов.
- Очистка хранилища браузера удаляет прогресс; это ещё не сохранение в БД.
- В настройках есть таймер до 00:00 UTC и правила с примерами.
  Переключатель напоминания — неактивная заглушка; уведомления не создаются.
- Крестик закрывает Mini App, если среда уже предоставляет Telegram API.
  В обычной вкладке без права закрытия показывается локальный экран
  сворачивания с возвратом к сохранённой игре. SDK и боты не подключаются.
- Других режимов и языков нет.
- Сервер слушает только `127.0.0.1` и **не предназначен для публикации в интернет**.
- HTTP отдаёт только HTML/CSS/JS и игровые ответы; Python-исходники, словарь,
  каталоги, `.env` и другие файлы проекта не раздаются.

`?scene=stats` и `?scene=settings` открывают нужный экран. Старые демонстрационные
`scene=win/loss/empty` больше не подменяют партию.

## Тестовый Telegram-режим

`telegram_server.py` — отдельный процесс, не часть polling основного бота.
Он допускает только `APP_ENV=test`, проверенную локальную тестовую БД
и совпадение токена с `EXPECTED_TEST_BOT_ID`. Доступ ограничен `OWNER`
и `ADMIN_LIST` из тестовых настроек. В production игра выключена по умолчанию;
она включается отдельно через `WORDLI_ENABLED=true` и рабочий HTTPS-адрес.
Рабочий HTTP-сервер запускается другим entrypoint, см. [инструкцию production](PRODUCTION.md).

Запуск из корня проекта с уже подготовленным HTTPS-туннелем:

```powershell
$env:APP_ENV = 'test'
.\.venv\Scripts\python.exe -B -m prototypes.wordli.telegram_server --port 8770 --public-origin https://YOUR-TEST-HOST --env-file .env.test.local
```

Сам процесс слушает только `127.0.0.1`. Внешний HTTPS должен вести только
к его порту, не к `local_server`, БД или каталогу проекта. Для временной
проверки разрешён Quick Tunnel Cloudflare; это не production-развёртывание.

В `.env.test.local` задаётся `WORDLI_WEBAPP_URL=https://YOUR-TEST-HOST`.
Затем запускается только тестовый бот:

```powershell
.\.venv\Scripts\python.exe -B -m testing.run_wordli_test_bot
```

Нижняя кнопка называется «Игры 🕹». Она открывает меню с inline WebApp-кнопкой
«5БУКВ», запускающей приложение с подписанным `initData`. Для этого режима
официальный Telegram SDK добавляется сервером; обычный локальный HTML
и другие миниаппы его не получают.

При выборе «Игры 🕹» бот сначала отправляет отдельное сообщение «🕹»
и удаляет свою нижнюю reply-клавиатуру. Затем показывает приглашение
«В какую игру сыграем?». Первая строка содержит кнопки «5БУКВ» и
«Битва Измерений», вторая — прежнюю «Назад на главную ↩️».
«Битва Измерений» показывает только всплывающее уведомление
«Игра в разработке», не меняя меню и прогресс игры.
Возврат удаляет только приглашение и восстанавливает обычную главную
клавиатуру. Системная клавиатура телефона управляется клиентом Telegram.

В приглашении и на кнопке используется обычный Unicode-джойстик, без
custom emoji и эффектов сообщения. Старые настройки `WORDLI_CUSTOM_EMOJI_*`
сохранены для совместимости, но на эти два элемента больше не влияют.
Старые кнопки «Слова 🧩», «Слова 🕹» и «Слова» продолжают работать в тестовом режиме.
Конфетти остаётся только внутри игры после новой победы.

Для получения ID тестовый бот умеет один раз принять отдельный custom emoji
от владельца/администратора в личном чате. В игнорируемый
`.test-data/wordli-runtime/custom-emoji.json` записываются только ID и
Unicode-замена. Подстановка из этого файла автоматически не выполняется:
ID и разрешение отправки Telegram проверяются перед ручной настройкой.

API проверяет HMAC, возраст подписи и список разрешённых пользователей.
Пользователь берётся только из подтверждённого Telegram ID, не из JSON
клиента. Неподписанный запрос не имеет доступа к прогрессу. Секреты,
словарь, Python-файлы и произвольные каталоги через HTTP не выдаются.

### Серверное сохранение

- Только отдельные таблицы `wordli_profiles`, `wordli_requests` и `wordli_settings`.
- История с закреплёнными ответами, черновик и версия словаря находятся
  в тестовой БД. Это постоянный личный список использованных слов; клиент
  его не получает. Статистика
  пересчитывается сервером по этой истории; клиент не может прислать счёт.
- Серверный режим не читает и не записывает локальную историю браузера.
  Переноса старого локального прогресса автоматически нет.
- Запросы содержат ревизию; устаревшее устройство получает актуальное поле.
- Ходы и повторная игра используют UUID: повтор запроса не списывает
  попытку и не создаёт ещё одну партию.
- Черновик автоматически сохраняется с задержкой 250 мс. Собственный
  крестик дожидается записи. При скрытии/закрытии страницы дополнительно
  выполняется `keepalive`-сохранение. При аварийном завершении или отсутствии
  сети последняя ещё не доставленная правка не гарантируется.
- После нового входа с того же Telegram-аккаунта состояние восстанавливается
  из БД независимо от устройства и `localStorage`.

POST `/api/draft` принимает `day`, `index`, `draft`, `revision`.
`/api/guess` и `/api/next` дополнительно требуют `revision` и `request_id`.
`/api/state` принимает пустой объект. `history`, `user_id` и `stats` от
браузера запрещены. Подпись передаётся в `X-Telegram-Init-Data`, а не в URL.

Для локального запуска SQLite используется существующая изолированная
`.test-data/copilot_review.sqlite3`. Перед добавлением таблиц игры сохраняется
резервная копия. PostgreSQL-путь предусмотрен, но без отдельного прогона
на PostgreSQL его нельзя считать проверенным deployment.

Временные адреса и PID запущенного стенда находятся в игнорируемом
`.test-data/wordli-runtime`. После остановки туннеля адрес недоступен;
новый Quick Tunnel создаст новый адрес, который нужно обновить только
в тестовых настройках и перезапустить только тестовые процессы.
