## Локальная проверка в branch-gpt-review

По умолчанию приложение запускается в **тестовом** режиме и читает только
`.env.test.local`. Настоящий токен хранится только в этом исключённом из Git
файле. Шаблон без секретов — `.env.test.example`. Боевой режим требует явного
`APP_ENV=production`; обычный `.env` в тестовом режиме не загружается.

### Автоматические проверки без Telegram

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-test.txt
.\testing\run_checks.ps1
```

Рабочая версия Python проекта — 3.11. На этом ноутбуке исходное окружение 3.11
повреждено; отдельный `.venv` создан на доступном Python 3.10 для офлайн-проверок.
Для точного прогона 3.11 предусмотрен `Dockerfile.test`.
Если локальная сеть использует собственный доверенный центр сертификации,
передайте pip правильный CA-файл через `--cert`, **не отключайте проверку TLS**.

Pytest ограничен каталогом `tests`; старые ручные сетевые скрипты из `testing`
автоматически не запускаются. В автотестах запрещены настоящий Telegram и
внешние HTTP-запросы. PostgreSQL/Redis-тесты без выделенного стека пропускаются.

### Искусственные данные и изображения

`testing/prepare_fixtures.py` воспроизводимо создаёт 120 пользователей, 5 рецептов,
30 результатов игр и 5 PNG с чёрным текстом на белом фоне. JSON и PNG находятся
в `testing/fixtures`. Рецепты используют `test-fixture:1` ... `test-fixture:5`:
локальные картинки разрешены только для тестового бота, не для боевого режима.

```powershell
.\.venv\Scripts\python.exe -m testing.prepare_fixtures
.\.venv\Scripts\python.exe -m testing.seed_test_data --database-url "sqlite+aiosqlite:///.test-data/copilot_review.sqlite3"
```

Заполнение проверяет назначение БД **до подключения**, не удаляет таблицы и записи.
Повтор идентичных фикстур ничего не добавляет; коллизия с другими данными прерывает
операцию. Боевые данные не копируются. Данные SQLite хранятся только в `.test-data`.

### Выделенные PostgreSQL и Redis

Только после разрешённого запуска Docker Desktop:

```powershell
docker compose --env-file .env.test.local -f docker-compose.test.yml build test-runner
docker compose --env-file .env.test.local -f docker-compose.test.yml up -d db-test redis-test
docker compose --env-file .env.test.local -f docker-compose.test.yml run --rm test-runner
```

Этот стек имеет собственные сети и тома, без фиксированных имён контейнеров и
без публикации портов БД/Redis. Bootstrap создаёт непривилегированный `bot_app`
только в `copilot_review_test`. Пароли `REVIEW_DB_ADMIN_PASSWORD` и
`REVIEW_DB_APP_PASSWORD` должны быть отдельными случайными локальными паролями.
Право `CREATE` на эту тестовую БД нужно только для изолированных UUID-схем
проверки миграции; роль не получает `SUPERUSER`, `CREATEDB` или `CREATEROLE`.
Не используйте обычный `docker-compose.yml` для тестового запуска.
Проверка Compose выполняется с `config --quiet`, чтобы не печатать секреты.

Полный прогон включает настоящий PostgreSQL/Redis, конкурентные подтверждения
платежа, запуск/закрытие зависимостей приложения и SQL-миграцию на синтетической
старой схеме. Миграционные тесты создают и удаляют только собственные UUID-схемы;
копия настоящей базы не используется. Вызовы Telegram в автотестах заменены
заглушками, списаний Stars нет.

### Ручная проверка тестового бота

Команда `.\testing\run_test_bot.ps1` запускает только тестовый токен и тестовую БД;
остановка — Ctrl+C. Служебные группы выключены. Реальные платежи не выполняйте.
Сначала откройте тестового бота и отправьте `/start`; ID администратора добавляется
только в локальные тестовые настройки, не в общие фикстуры.
Для проверки WebApp нужен **отдельный HTTPS-адрес** с версией этой ветки.
Без него меню честно сообщает, что мини-приложения не настроены. Боевой Pages
не переключается на тестовую ветку; JS сначала проверяется SDK-заглушкой.

### Перед будущим выпуском — отдельно, не автоматически

- На существующей PostgreSQL потребуется проверенная миграция
  `database/migrations/001_review_payments.sql`: новая `payments` и nullable
  `games.user_name`. Сейчас этот SQL на VPS **не применялся**.
- В production автоматическое изменение схемы выключено. Нужны резервная копия,
  проверка восстановления и отдельное разрешение на миграцию/развёртывание.
- До миграции проверить владельцев существующих таблиц. Миграция должна создавать
  `payments` от прикладной роли либо явно выдавать ей необходимые права на таблицу
  и sequence; успешная миграция от администратора сама по себе этого не гарантирует.
- Старые неоплаченные счета с прежним payload нужно выпустить заново; исторические
  платежи не импортировались в новый реестр. Это ограничение нужно согласовать
  перед выпуском. Возврат через Telegram и запись результата в БД не образуют
  общую транзакцию: при сбое записи требуется сверка, пользователь получает сообщение.
- Не удалять `payments` ради отката кода: это уничтожит историю новых платежей.
- PostgreSQL, Redis, их тома и основной бот не изменяются локальными проверками.

### Согласованный объём выпуска 2026-10-31

- Мини-приложения выпускаются в текущем виде, без отдельной ручной проверки
  через тестовый HTTPS-адрес. Этот остаточный риск принят владельцем проекта.
- Старые счета не переносятся и не обрабатываются новой версией. Исторические
  платежи автоматически не импортируются; старые записи при выпуске не удаляются.
- Разрешены объединение в `main`, отправка в GitHub и выпуск на VPS после
  резервной копии с проверкой восстановления. Пересоздаётся только бот;
  PostgreSQL, Redis и их тома сохраняются.

## Четыре языка интерфейса

Бот поддерживает русский (`ru`), английский (`en`), испанский (`es`) и украинский
(`uk`). В настройках первая строка выбора остаётся EN/RU, вторая — ES/UK.
Подписи языков переводятся на текущий язык интерфейса. Сохранённый выбор имеет
приоритет над языком Telegram и сохраняется после повторного `/start`.
Для нового пользователя региональные коды вроде `es-MX` и `uk-UA` приводятся
к базовому языку. Новые таблицы и миграции БД для этого не требуются.

Каталоги `.po` и собранные `.mo` лежат в `locales/<код>/LC_MESSAGES/`.
Активные ключи извлекаются из публичных модулей по тому же списку, который
контролирует `tests/test_translations.py`. Все четыре каталога должны быть
полными и собранными; переключение языка не вызывает внешний переводчик.

Исключения остаются прежними:
- админка и пять служебных событий — только русский;
- рецепты — русский для RU, английский для остальных локалей;
- устаревший английский рецепт остаётся видимым, отсутствующий заменяется
  русским оригиналом;
- интерфейс и словарь Mini App «5БУКВ» — только русский, приглашение,
  напоминание и предупреждение о языке игры переводятся на язык бота;
- коды команд, callback, валют и платежей, формула очков и данные не меняются.

Добавление ES/UK в этой ветке проверяется локально. Это не разрешение на
обновление рабочего бота, основной БД или VPS.
